# 外部听写桥功能规格

## 目标

让用户通过可配置的手柄按键触发 Spokenly 等外部听写工具，并将转写文本写入 JoyDSH 当前有效的文本输入目标。JoyDSH 只桥接交互，不负责录音、转写或自动提交文本。

## 交互契约

- 手柄语音输入键默认映射为 `R3`，用户可在设置中改为其他支持的按键。
- 用户选择的语音映射优先于该按键原有的 JoyDSH 语义动作；设置界面必须明确提示被替代的动作。
- 手柄按下与松开事件原样转交给外部听写工具。对于 Spokenly 的 `automatic` 模式：
  - 短按后松开进入切换听写，再次短按结束。
  - 长按进入按住说话，松开结束。
- 界面语音按钮和 JoyDSH 键盘快捷键只产生一次完整短按。
- 如果当前焦点是有效文本输入目标，则保留该焦点并交由外部听写工具写入。
- 如果当前没有有效文本输入目标，则先聚焦前台任务的任务输入框，再触发外部听写工具。
- 转写结果只写入输入框，不自动发送给智能体运行时。

## 状态与反馈

- 外部听写工具是录音状态的事实来源。
- JoyDSH 只显示手柄按键正在按下或触发请求已发出的瞬时反馈，不维护推测性的“正在听写”持久状态。
- 设置中的测试操作只能声明模拟按键事件已发出，不能把事件发送成功表述为外部听写工具已经开始录音。

## 配置与兼容

- 提供 Spokenly 预设，默认模拟右侧 Command 键，并保留其他外部听写工具和自定义键码的映射能力。
- 新配置默认使用 `R3`。已经明确保存的用户按键映射继续保留。
- 旧版 Toggle / Push-to-Talk 配置不再决定桥接行为；读取旧配置时迁移为统一的按下/松开语义。
- 首期完整验收范围为 macOS 与 Spokenly。Windows 保留通用按键模拟能力，但不承诺与 Spokenly 相同的短按/长按行为。
- macOS 将辅助功能信任作为按键模拟的运行前提。JoyDSH 必须检测当前信任状态、提供系统授权入口，并在未授权时拒绝模拟且显示可执行的错误信息。

## 非目标

- 不在 JoyDSH 内实现录音、语音识别或文本润色。
- 不读取或推断 Spokenly 的内部录音状态。
- 不在转写完成后自动发送任务消息。
- 不将集成限定为 Spokenly 专用协议。

## 验收标准

- `R3` 的按下和松开只各产生一次对应的系统按键事件。
- 短按 `R3` 可通过 Spokenly 开始或结束切换听写。
- 长按 `R3` 可通过 Spokenly 开始听写，松开后结束并把文本写入目标输入框。
- 当前已聚焦的有效文本输入目标不会被任务输入框抢走焦点。
- 没有文本输入目标时，前台任务输入框会在听写开始前获得焦点。
- 语音输入按键与已有动作冲突时，界面可见地说明原动作将被替代。
- macOS 未授予辅助功能权限时，测试操作不得显示成功；授权完成并返回 JoyDSH 后，界面必须刷新为已授权状态。
- JoyDSH 不展示可能与 Spokenly 脱节的持久录音状态，也不会自动发送转写文本。
