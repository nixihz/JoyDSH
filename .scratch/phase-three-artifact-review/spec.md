# 阶段三：任务成果评审

## 目标

让用户在任务回合停止后，通过 TV 优先界面检查任务产生的文件变更，逐文件接受或拒绝，并能安全回滚或提交已确认成果。

## 范围

- 以任务开始时的 Git 状态作为不可伪造的本地成果边界。
- 显示任务文件清单、结构化差异和成果汇总。
- 持久化逐文件接受状态；内容再次变化后自动回到待评审。
- 所有拒绝和回滚操作必须携带 Rust 服务端生成的快照令牌，并在首次写入前重新验证。
- 任务运行中禁止成果写操作；逐文件高频操作使用语义动作，任务级回滚和提交进入命令中心。
- 请求智能体生成提交说明，用户确认后精确提交已接受成果。

## 安全边界

- 不使用 `git reset --hard`、`git clean` 或无约束递归删除。
- 不为恢复任务补造基线，不把任务开始前的脏工作区归为任务成果。
- 客户端不得生成或推断 `changeId`、`snapshotToken`。
- 陈旧快照、HEAD 前进、冲突或 Git 操作进行中必须失败并返回最新快照。
- 当前仓库没有初始提交；本功能实现不得顺带创建提交。

## 验收

- 文本、二进制、大文件、暂存区、执行位和符号链接内容变化都会使快照失效。
- 接受状态在应用重启后保留；已接受文件再次变化后显示为待评审。
- 单文件拒绝只影响该变更；任务回滚要么完整成功，要么在首次写入前失败。
- 1280×720 与 760×600 下无横向溢出，核心评审流程可用手柄、键盘和鼠标完成。
- Rust、TypeScript 全量测试、静态检查与构建通过。
